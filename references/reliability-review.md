# Agent 与长任务可靠性审查

仅在用户要求此类审查、正在排查长任务故障，或改动实际触及这些机制时加载。先找到项目既有 owner、状态机和协议；以下是审查问题，不是要求新建功能。

需要设计任务集、评分器或比较模型/提示/运行时版本时，读取 [agent-evaluation](../skills/agent-evaluation/SKILL.md)。本参考定位运行机制故障；通用评测提供跨任务的判定与比较，均复用项目现有入口。

## 按故障面分工

有适当授权和工具时，可把 runtime/恢复、trace/tools、跨端资源分别交给独立审查者。主 Agent 合并相同根因，以证据和影响排序。第一轮只读，确认后分配互不冲突的修复范围。

| 故障面 | 重点验证 |
| --- | --- |
| 推进与终态 | 总 deadline、局部 timeout、步数/token/retry 预算，等待用户与无进展循环，异常/超时不能留下永久 running 或假成功 |
| 取消与订阅 | 客户端断开、用户取消和 worker 停机分别对应什么语义；durable job 不因订阅断开误终止，普通子流按 owner 清理 |
| 持久化与恢复 | checkpoint 前后、写副作用后未保存结果、终态提交后未通知的崩溃窗口；旧 worker 不能覆盖新 lease 的结果 |
| 幂等与重试 | 重复 delivery、并发 claim、超时结果未知，跨层重试次数相乘；用实际副作用次数证明幂等 |
| 事件与前端 | 序号单一 owner、持久化与通知顺序、丢通知回退、重放去重、游标不越过未接受事件、旧连接不污染新会话 |
| 资源与积压 | iterator、task、锁、连接池、订阅、缓存、context 与队列在反复运行后是否有界；慢消费者是否触发无界缓冲 |
| Tools | registry/schema/真实 callable 一致，执行端校验能力与资源归属，未知参数明确拒绝，副作用与只读操作采用不同重试规则 |
| 上下文与证据 | 外部内容保持不可信来源，不能提升工具权限；裁剪保留必要约束和工具调用/结果配对，大输出使用已有 artifact 机制 |
| Trace | request/task/run/attempt/tool-call 关联不串用户，成功/失败/等待/取消符合既有生命周期，进程崩溃不伪造完成 |
| 遥测降级 | exporter/flush/store 失败不重复业务主体、不遮蔽原异常、不无界积压；日志脱敏，metrics label 避免无限基数 |

## 特别需要区分

- span、持久化事件、UI projection 和业务权威状态职责不同，不为了“完整 Trace”建立平行写路径。
- 参数预拒绝、等待确认、缓存重放不一定有 started → completed；依据已有契约判断。
- 副作用结果不明需要现有恢复策略，不能靠重试宣称 exactly-once。
- 已接受架构安排、缺少某种 SDK/看板、单纯缺测试，不自动构成 Bug。
- Trace 可记录结构化动作与安全摘要，不要求收集模型内部思维链、凭据或敏感用户原文。

## 证据与修复

每项输出：触发条件、文件/符号、根因、违反的不变量、实际影响、证据与最小修复点。用“待验证 / 已确认 / 已修复并验证 / 被阻塞”区分状态；优先关键路径故障与数据风险，不为数量制造发现。

复用已有生命周期、恢复和工具测试。测试应在修复前暴露目标问题，修复后通过，并断言终态、业务产物、副作用次数和清理。跨端/API/权限语义变更依项目规则处理，不降低架构棘轮。

可能泄漏或积压时，安排有总时限的本地重复执行：先预热，再记录实际次数、并发、活跃任务/连接/订阅、队列与内存趋势。区分一次性缓存增长与持续线性增长，短测结论仅覆盖实际条件。
