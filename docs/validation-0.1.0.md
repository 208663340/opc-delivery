# OPC Delivery 0.1.0 — 验证记录

验证日期：2026-10-22（Asia/Shanghai）。本记录描述技能创建时的测试，不代表已经验证所有真实生产场景。

## 交付范围

- 一个技能入口，按需加载需求、开发、验证、可靠性审查与发布流程。
- 项目接入模板和可选发布证据模板。
- 两个 Python 标准库工具：只读项目识别、发布证据元数据一致性检查。
- 保持自动发现默认策略；不绑定最初项目的技术栈、云平台、地址或凭据。

## 结构与脚本

- 官方 quick_validate.py：通过。
- Markdown 相对链接：全部存在。
- 三个 Python 文件：语法编译通过。
- scripts/test_delivery_tools.py：22 项测试通过。
- 在现有 monorepo 上只读试运行，找到 63 个入口文件和 12 条候选命令；明确报告有限深度覆盖，不执行这些命令。
- 文件扫描未发现原项目名称、个人路径、服务器地址或原账号标识进入技能内容。

工具测试覆盖旧提交、错误产物、环境错配、未运行/阻塞测试、缺失业务冒烟、缺少证据、重复 JSON key、输入类型异常、符号链接、不执行 package scripts，以及不执行 Git fsmonitor/clean filter 等边界。

项目识别工具主动保留 dirty=unknown：Git 工作区比较可能执行仓库 clean filter，因此在信任仓库配置后由调用方单独核对状态。不能把 unknown 当作 clean。

## 三个独立隔离任务

测试 Agent 未继承制作过程，也未获得预期答案；只收到技能路径、请求和原始材料。

| 场景 | 实际结果 | 评估 |
| --- | --- | --- |
| 模糊产品想法，只有两个晚上 | 生成标准库 CSV 原型、验收样例和判断记录；5 项测试通过；原始数据未改；明确商业需求和付费尚未验证 | 满足本场景要求 |
| 空异常消息导致 upload failed: null | 新回归先失败，修复异常基类消息传递后 3 项测试通过；原额度规则和未提交用户笔记保留 | 满足本场景要求 |
| 声称上线成功，证据实际不一致 | 找到旧提交测试与实际失败的业务冒烟；区分健康、部署和验收；保留原始记录；未虚构凭据需求或重复申请已批准操作 | 满足本场景要求 |

主 Agent 复跑两个代码产物的测试，均通过；检查了发布审查结论和原始材料对应关系。

## 结果边界

这是格式、脚本和三个模拟任务的行为验证。没有访问真实生产、发送消息、消费付费模型、执行真实部署或验证商业效果。没有与默认 Agent 或其他技能做控制变量对照，因此不报告效率提升百分比。

发布证据检查器只判断元数据一致，不打开 evidence、不核验日志真实性、不判断授权；业务失败仍需读取原始证据。不同平台的真实发布需要按项目规则继续验证。
