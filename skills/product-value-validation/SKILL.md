# 上线后的产品价值验证

回答“谁在什么情境下取得了什么价值，证据是否足以支持下一步投入”。先沿用产品已有目标、事件定义和主记录；一次留存分析无需新建分析平台，普通发布也不自动扩展成长期增长项目。

## 从决定和现有证据进入

写清本轮要决定的是继续试用、改进、扩大、收费还是停止，以及现有版本、目标人群、投入上限与已有门槛。把价值表述为用户完成的结果，例如“在需要时独立生成正确的交付物”；访问、点击、模型回复和口头认可只能是过程或线索。

| 当前问题 | 读取或采用 | 能支持的结论 |
| --- | --- | --- |
| 已有事件、订单或使用记录，价值是否持续 | [价值记分表](assets/value-scorecard.md)；核对口径后计算 | 这批用户、这段窗口内实际观察到的结果与缺失 |
| 改版是否改善结果，下一轮怎样验证 | [测量与实验方法](references/measurement-and-experiments.md)、[实验简报](assets/experiment-brief.md) | 与研究设计匹配的比较及继续条件 |
| 不知道为何不用、用户情境不清 | [user-research](../user-research/SKILL.md) | 可追溯的行为解释与反例 |
| 用户卡在流程中，需观察操作 | [prototype-validation](../prototype-validation/SKILL.md) | 特定任务的独立完成与障碍 |
| 服务不可用或部署版本有误 | [deployment-operations](../deployment-operations/SKILL.md) | 运行恢复证据；健康状态不证明产品价值 |

模板字段可合并进现有记录，不要求复制整份模板或维护第二套指标。必要的业务取舍带建议交给用户；缺少阈值不妨碍分析现有数据和准备下一步。

## 先检查测量是否可信

1. 固定分析单位、合格人群、首次曝光/分配时点、版本、时区、事件含义、去重键和截止时间。核对事件能否回到真实产物或完成状态；事件改名不代表语义相同。
2. 分别记录符合条件、实际曝光、进入观察窗、窗口完整及采集缺失的数量。新用户尚未成熟与成熟用户没有价值事件不同；失去采集不等于流失。
3. 检查重复、身份合并、内部/机器人名单、延迟上报、版本混用与对账缺口。保留原始数据和修正依据；不能为了指标好看事后筛掉失败、退款或低频用户。
4. 前后对比先查人群、渠道、时间和人工帮助是否同时变化。无法对齐时，仍可描述各组事实，但暂停因果归因。

## 计算和解释

- 先报原始计数与分母，再报比例。首次价值、重复价值、付费、退款后收入分别计算；累计发生过一次的比例不能冒充相同观察时长的激活率。
- 留存写明 cohort 起点和后续窗口的精确边界。保留未成熟、缺失与观测完整的不同状态；缺失较多时给出能支持的上下界或敏感性分析，不能将其称为统计置信区间。
- 结合自然需求周期看重复价值。可以补充“再次有需求机会时”的指标，但必须另列口径与机会数据来源，不能追溯替换既定分母。被产品影响的机会或活跃状态不宜用作筛选条件来证明效果。
- 将独立成功与受助成功、节省时间与转移给人工的成本分开。退款、支持时间及用户损失可推翻表面增长；支付意向、订单、到账、退款和续费不能混算。
- 观察性数据支持关联；可信随机对照才有条件支持对应干预的因果判断。小样本或区间很宽时保留“不足以决定”，不能把未显著等同于没有作用。

## 选择最小的下一轮

先处理最能改变决定的缺口。埋点语义错误先对账；行为原因不清做定向研究；已有可信基线且流量、预算适合时才设计随机实验。流量不足可用限量试用、真实任务观察与后续复访，明确这些设计不能证明总体提升。

实验开始前固定价值假设、主指标、护栏、数据质量检查、观察窗口、最小值得投入的改善及其决定来源。安排分配单位、样本/时间预算、分析与停止规则；未知项标待定，不编造通用转化率或人数门槛。新增联系、收费、线上配置或实验操作按当前实际授权执行；已授权不重复询问。

## 交回结果

交付：当前支持的决定、版本与证据、可复核计算、反例和未知、下一项最小动作及改变决定的条件。区分“方案已准备”“实验已执行”“产品价值已观察到”，不要把三者合并宣称完成。已有验收满足后结束本次任务；持续监测仅在用户要求时安排。
