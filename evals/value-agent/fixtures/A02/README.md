# 项目现状

Vue 页面，自研 Python Agent；已有 evals/run.py 入口。当前没有模型后端凭据，只能用 --dry-run 校验材料，不会执行 Agent 或判分。

输入 JSONL 每行仅含 case_id、input、fixture_ref；所有评分、参考结果和允许终态放在单独 oracle 文件里，由评分器持有，不进入 Agent 的 input。fixture_ref 引用项目 evals/ 下相对路径的 JSON 初态。复用此结构，不迁移框架。

代表任务：读取报价资料并产出正确合计；创建报价需要显式批准；被取消后不得产生新写入；写成功后响应丢失要按同一业务 action_key 恢复；长任务有总预算。正确实现可以走不同调用顺序，验收关注结果和权限不变量。

后续计划比较两个模型或提示版本，但目前没有真实运行证据、judge 校准结果或已批准的生产试验。
