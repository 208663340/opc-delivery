# 发布与恢复方法

## 从现有系统形成操作步骤

先找项目的部署入口、产物记录、环境 owner 和历史 runbook。使用实际部署单元，不因为有此 Skill 引入容器、集群或新云服务。源代码通过测试后，还要核对构建内容、目标架构、运行配置和实际服务版本。

将每一步连接起来：前置证据 → 具体对象与操作 → 预期结果 → 观察窗口 → 停止条件 → 恢复选项。运行前核对权限和目标，执行后记录原始结果；`planned`、`not_run`、`failed` 不能换成 `passed`。测试流量的写入、发送和第三方计费也要符合任务范围。

## 兼容性矩阵

| 变化 | 发布前核对 | 恢复时核对 |
| --- | --- | --- |
| 应用与配置 | 必需配置/功能开关已就绪，配置引用可追踪 | 旧应用是否仍认识当前配置与外部接口 |
| schema 与数据 | 新旧应用/worker 能否共存，迁移锁与数据范围 | 删除/重命名字段后旧应用能否工作，数据语义是否仍兼容 |
| 队列与在途任务 | 消息版本、幂等键、并发与重试行为 | 旧 worker 能否处理新消息，重复执行如何识别与对账 |
| 外部副作用 | 请求身份、超时后状态查询、去重策略 | 已发送/扣款的结果不会因回退二进制自动撤销 |

当旧版本仍要运行时，优先评估先扩展、兼容过渡、确认消费者迁移、再收缩的变更顺序。不能由方法名推出迁移安全：字段默认值、索引、约束、事务和锁的行为按实际引擎/版本核对，并在有代表性的数据上验证。PostgreSQL 的常量默认值新增列与逐行重写不是同一回事，不传播旧版本的笼统结论。

## 放量、观测与停止

项目已有机制支持时，先在有限范围验证，再扩大影响。比较同时间、同路径的候选与基线，关注分组流量和样本量，避免整体平均掩盖候选失败。事先确定谁可停止和采取哪种恢复动作。

至少检查：服务版本、健康/就绪、关键用户任务及其副作用、错误与延迟、资源和必要的异步信号。健康接口成功但任务重复、结果错误或授权失败时，业务验证仍失败。遇到明显退化应停止推进；无需为了填满固定观察窗口继续扩大影响。

若项目使用 Kubernetes，区分 startup、readiness 与 liveness 的用途，探针阈值结合服务启动和故障模式；不能把重启当作所有故障的修复。若使用 Docker，按实际环境核对分阶段构建、可信且可追踪的基础镜像、构建上下文排除敏感文件、适当非 root 运行、退出处理和资源约束。变更前评估应用依赖；无需容器化才能完成运维评估。

## 恢复与备份

RPO 是业务对数据损失窗口的目标，RTO 是恢复时间目标；目标和实测结果分列。备份文件存在不等于可读、完整、含有所需对象或能在目标时间恢复。

恢复演练先选隔离目标与受控数据，核对备份时间、校验、解密/工具可用性、恢复流程和业务一致性。记录实际恢复点、耗时、缺失范围与失败步骤。不要为了验证而覆盖生产。生产恢复须另明确目标、写入冻结或隔离、现场保留、恢复后对账和新写入的损失边界。

旧应用依赖已删除字段时，不能声称“回旧镜像即可恢复”。先停止不兼容回退，评估暂停变更/隔离受影响路径、兼容前向修复或具备数据证据的恢复方案。添加同名空字段也不等于原数据恢复。

## 日常值守与事件闭环

告警围绕可行动的用户影响，附环境/版本/时间、观测链接、负责人、升级路径和首个检查。日常检查按实际风险安排：恢复演练、容量趋势、证书/依赖到期、积压、失败任务与资源限额。

事件记录区分事实、假设与动作：何时观察到什么、为什么选该动作、谁对哪个对象做了什么、结果如何。业务恢复后核对残余重复任务/数据与用户影响，再处理根因和复盘。对外沟通使用已有授权与渠道，评估本身不授权发送通知。

## 方法来源

以下官方资料于 2026-10-22 核对；部署命令及平台规则仍按项目实际版本查证：

- [Google SRE Workbook：Canarying releases](https://sre.google/workbook/canarying-releases/)：限制变更影响，比较候选和控制组，连接监测与发布决策。
- [Google SRE Book：Monitoring distributed systems](https://sre.google/sre-book/monitoring-distributed-systems/)：围绕延迟、流量、错误、饱和度和可行动告警设计监控。
- [Docker：Build best practices](https://docs.docker.com/build/building/best-practices/)：构建阶段、上下文、基础镜像和可复现构建。
- [PostgreSQL：Modifying tables](https://www.postgresql.org/docs/current/ddl-alter.html)：按具体 DDL 和版本判断表变更与数据影响。
- [Kubernetes：Liveness, readiness and startup probes](https://kubernetes.io/docs/tasks/configure-pod-container/configure-liveness-readiness-startup-probes/)：区分探针职责，按服务行为配置。
