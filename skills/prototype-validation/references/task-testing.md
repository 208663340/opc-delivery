# 任务测试方法

## 原型保真度跟随未知

先挑一个会改变实现方向的问题。草图适合讨论信息关系，但不能测真实加载性能；可点击原型能暴露导航与措辞障碍，但模拟支付无法证明扣款成功。高风险技术可以先做短实验，记录输入、环境、结果和失败条件。避免为了“看起来完成”提前实现未验证的全流程。

为每轮保留版本或截图引用、测试入口、数据重置方法、模拟范围。任务要求必须在原型里可完成；若原型缺少目标能力，记录原型覆盖缺口，不归因为参与者能力不足。

## 中性任务与主持

任务例：“你准备把含税报价交给这位客户，随后发现内容有误。请完成你认为需要的操作。”成功标准由研究者预先记录，不在任务里提示按钮、菜单或路径。

开场说明：我们在检查产品是否容易使用，没有标准答案；可随时暂停或退出。请按平时习惯操作，愿意时说出想法。屏幕上的哪些动作是模拟，哪些真实生效，要提前说明。

参与者停顿时，先观察；可以问“你现在在找什么？”或“你预期会发生什么？”。避免“是不是右上角那个？”等指路。必须提供帮助时如实标记受助；用户询问“这样对吗”时可问其预期，不以肯定暗示答案。结束后询问最困难处、预期和替代做法，满意度作为补充自述，不替代观察结果。

## 计数与可追溯分析

一个结果单元是某会话对某任务的尝试。人、会话、任务分别计数。独立完整成功、受助完成、部分完成、失败、放弃按事先定义记录；时长缺失保留为空，不能补成 0。原型故障中断另列，并说明是否已经进入任务与如何处理分母。

报告先给计数，再给比率：分子是什么、分母是什么、排除了什么。自动化脚本只说明脚本在该环境的行为，不是一个真人样本。技术失败即使不进入可用性完成率，也属于原型可用程度的重要发现。

问题条目至少包含：观察位置 → 用户目标受什么影响 → 支持与相反证据 → 可能原因 → 最小改动假设 → 复测方法。优先处理阻断与错误结果，避免仅凭个人审美排序；一次出现也可能很严重，多次出现也不证明普遍发生。

## 方法来源

以下官方资料于 2026-10-22 核对；本文件将方法转为交付中的操作提示，不设通用样本量或通过率：

- [GOV.UK：Moderated usability testing](https://www.gov.uk/service-manual/user-research/using-moderated-usability-testing)：招募相关用户、准备任务并观察实际尝试，任务避免透露答案。
- [Digital.gov：Usability testing](https://digital.gov/guides/research-collaboration/testing/usability)：围绕研究目标选择原型与测试材料，准备任务、参与者说明和记录。
