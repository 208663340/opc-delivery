# 发布：把版本、产物和业务证据连起来

用于构建交付、部署、上线排障与回退。优先复用项目已有发布机制。本文件不指定云厂商，也不要求使用容器。

需要渐进放量、监控值守、迁移兼容性或恢复演练时，继续读取 [deployment-operations](../skills/deployment-operations/SKILL.md)，复用其运维手册或项目已有 runbook。简单发布无需填写整套模板。

## 能力检查先于配置变更

1. 明确待发布源码及目标环境，记录当前服务版本和未提交修改；核对已有授权范围。
2. 用适当的只读操作检查已有 CLI 登录、仓库访问、SSH/平台连接和构建能力。已有凭据可用则复用，不先创建第二套令牌。
3. 权限不足、认证过期与网络故障分开定位；记录哪个操作返回了什么类别的错误，隐藏凭据。
4. 需要用户真人完成登录、扫码或认证时，说明具体原因和所需动作；独立准备工作继续。授权已完成后验证结果并推进，不重复确认。

凭据使用平台 Secrets、Keychain 或已配置的安全存储。可分享配置只包含示例与引用；不要求用户把 Token/私钥发到聊天，不将凭据放入命令参数、日志、源码或临时明文文件。

## 发布前应明确

| 项目 | 所需证据或决定 |
| --- | --- |
| 版本 | 本次提交与实际构建内容一致，必要时在隔离 checkout 构建，避免混入未提交文件 |
| 产物 | 不可变 digest、文件哈希或平台 deployment ID，可定位构建来源 |
| 检查 | 与版本对应的必要测试和构建记录，skip/失败原因明确 |
| 配置 | 目标环境所需配置已就绪，敏感值仍在安全存储 |
| 数据 | 有显式迁移入口，明确执行顺序、兼容性与备份/恢复要求 |
| 回退 | 可用旧产物或停服恢复方案；应用回退与 schema 回退分别判断 |
| 完成条件 | 健康、关键业务路径、版本核对与异常停止条件 |

首次发布可以采用明确的撤销/停用方案，不虚构“上一稳定版本”。若数据迁移不可逆，不能把重启旧镜像描述为充分回退。

## 网络与构建路径

构建/拉取慢时先检查失败阶段、目标 registry、架构和认证，再比较：已有 CI 构建、可访问的私有 registry、允许的服务器本地构建、已验证产物传输。

镜像加速器的支持范围需验证，不能假定它覆盖任意私有 registry。更换依赖源前验证可信来源与锁文件/哈希一致性，保留回退配置；不要关闭 TLS、盲换镜像或为了速度跳过测试。读取实时平台规则时使用官方资料。

## 实际执行

按项目流程完成构建、迁移、服务替换和检查。部署重入、重复点击与并发发布有实际风险时检查现有互斥机制。网络超时后先查询远端状态再重试，避免重复部署或迁移。

发布失败先确定“构建未完成 / 产物未到达 / 迁移失败 / 启动失败 / 健康失败 / 业务失败”中的位置。只有符合预先确认的回退条件才执行相应恢复动作，恢复后再验证。

页面仍旧时，依次核对源码包含的内容、构建产物、服务实际 digest/版本和客户端缓存响应。服务发的就是旧内容时，清缓存不能证明发布正确。

HTTP 200 或容器 healthy 只证明其检查范围。业务冒烟应覆盖用户关心的最短链路，使用获准的测试身份/数据，避免未经授权消耗付费服务。

## 可选的机器校验凭证

复杂的、以不可变 SHA-256 产物交付的发布可使用 `assets/release-receipt.example.json`。它是现有 CI/部署证据的索引，不替代真实证据，不构成第二套发布状态系统；有等价 provenance/manifest 就复用。

- `release`：目标源码提交、SHA-256 产物摘要与环境。多服务发布可对应包含各服务摘要的不可变 manifest；不能用单个服务的镜像代表整个系统。
- `checks`：真实执行记录；`test` / `build` / `deploy` / `smoke`。每个 passed 记录都需 evidence、scope 和同一源码提交。build/deploy/smoke 还需同一 artifact digest；deploy/smoke 环境必须等于目标环境。
- `claim`：`build_verified` 需要列出的 test/build 通过；`deployed` 还需 deploy 通过及具体 rollback_plan；`business_verified` 还需 smoke 通过。
- health probe 请记录在部署证据中。smoke.scope 写用户动作及成功断言，不能把单纯 healthz 当作业务检查。
- `not_run`、`failed`、`blocked` 不等于 passed。低一级声明可保留高一级失败记录，例如冒烟失败时仍可准确记录已部署，不能宣称业务验证通过。

```bash
python3 <本技能目录>/scripts/check_release_receipt.py <证据文件.json>
```

脚本不执行网络请求、不读取凭据、不运行 evidence 字段，也不核验日志内容或授权。退出 0 仅表示元数据支持所请求的声明；真人/Agent 仍需核对原始证据。非哈希平台发布用已有 deployment ID 证据，不为适配此脚本改造交付系统。
