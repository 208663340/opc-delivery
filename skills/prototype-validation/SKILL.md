# 原型验证

用足以支持下一步决定的原型，观察目标用户能否完成真实任务。先写清要验证什么，再决定做多精细；复用已有原型、设计系统和研究记录。

## 选择验证方式

| 关键未知 | 足够小的材料 | 可以支持的判断 |
| --- | --- | --- |
| 信息与术语是否理解 | 纸面草图、静态页面与任务问题 | 理解障碍和信息缺口 |
| 用户能否完成流程 | 可点击原型、已有产品的隔离测试环境 | 在该版本、任务和样本中的操作表现 |
| 接口、性能或技术是否可行 | 隔离技术实验、真实格式样本 | 该约束下的技术结果，另附测量 |
| 是否持续使用或付费 | [产品价值验证](../product-value-validation/SKILL.md) 中的实际试用、承诺或付费实验 | 相应真实行为；原型好评不能代替 |

目标用户与招募标准不清时读 [user-research](../user-research/SKILL.md)。需要制作界面且符合现有技术栈时，再读 [frontend-design](../frontend-design/SKILL.md)；验证不要求换框架或先做完整产品。

## 准备一次可观察的测试

1. 从已有目标提取待决策问题、真实场景和原型版本。标出哪些数据与动作是模拟，哪些会真实发送、扣费或写入；优先用可重置的测试数据。
2. 选择目标用户能理解的任务目标，提前定义完整成功、部分完成、失败和技术中断。任务不包含界面按钮名或操作答案；多个目标要分别记录，再判断整体完成。
3. 按 [任务测试方法](references/task-testing.md) 准备中性主持词，按需填写 [测试与观察模板](assets/usability-test.md)。联系、录制或向他人分享材料只在已有授权范围内进行。
4. 先做原型与环境的试跑，检查入口、数据、重置和记录方式；试跑及 Agent 浏览器检查单列，不能算真人可用性样本。

## 执行与记录

说明测试的是产品，参与者可以停止；按约定取得同意。让参与者尝试任务，观察操作、困惑、错误与自发解释，不教学、不以“点这里”引导成功。需要帮助时记录帮助内容和时点，不能再标为独立完成。

每个会话关联参与者匿名 ID、任务、原型版本、实际行为、结果和证据位置。记录“看到什么”与“为什么可能发生”两列，不能将分析者的解释写成用户原话。时间从事先定义的起点计，超时、放弃、空值和原型故障如实保留。

未接触真人时，交付测试方案或专家走查，并标为未执行。AI 扮演用户的反馈只能帮助检查材料，不能填进真人观察或招募完成数。

## 分析与决策

- 先列原始人数、任务开始数和各结果。独立完整完成率的分子仅含未受助的完整成功，分母说明有效真人任务开始数；受助部分完成和失败仍在分母。测试前原型加载失败等技术排除另列数量及原因，不能消失。
- 分别报告子任务与整体任务，不把“已提交报价”算成“提交且找到撤回”全部完成。重复会话与多个任务不能混作独立参与者人数。
- 用会话证据定位问题：阻止关键任务、造成错误结果、需要帮助、轻微摩擦。结合用户影响、出现范围和恢复代价排序；小样本次数不能推成总体概率。
- 每个重要问题给出改动假设、复测任务与继续/调整/暂停建议。修复后新版本单独记录，不覆盖旧观察。通过条件来自任务目标或既有基线；没有阈值就明确待建立。

交回：当前可支持的决定、对应版本和证据、优先问题与下一轮验证。可用性、需求、付费和生产可靠性分别判断，不能凭一次演示全部标为已验证。
