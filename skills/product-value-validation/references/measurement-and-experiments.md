# 测量与实验：让结果能改变决定

## 把用户目标落到数据

每个指标依次写“用户目标 → 可观察信号 → 计算口径 → 来源”。例如目标是减少月末对账劳动，信号应包含正确完成与人工时间，打开页面只能解释使用路径。错误产物、人工代做和后续返工会改变价值判断。

定义至少包含：单位（人/账户/组织/任务）、合格条件、分配与曝光、事件版本、去重规则、起止边界/时区、分子分母、成功证据、排除与缺失。组织内共享成果时，以个人随机化可能互相影响；分配单位、分析单位和不确定性计算应考虑这种关联。

缺少数据时先判断：没有发生、尚未有机会、窗口未结束、采集坏了、结果没有核验。不要统一填零。以某成熟队列 N 个单位为例，确认成功 S、确认未成功 F、结果未知 U，且 N=S+F+U，则成功比例只能确定在 S/N 至 (S+U)/N 之间。这是缺失结果界限，不含抽样误差；仅报 S/(N-U) 需要说明它只代表已观测子集，可能有选择偏差。

自然需求低频时，选择能覆盖实际周期的窗口。补充机会指标可帮助解释不使用，但机会的记录本身也可能缺失或受干预影响。保留预定主要指标，另列补充分析；不要先看结果再挑“最有潜力”的人群证明成功。

付款账本区分支付尝试、成功支付、结算、部分/全额退款与观察截止。按交易关联退款，分别报告历史购买者、仍有未退款金额者和净额；货币/税费/手续费口径明确。小额首购并不自动证明续费、价格适配或可盈利，成本与服务负担要单独核实。

## 先修测量，再解释增长

对一小批可追溯记录核对“事件 → 业务状态 → 真实产物”。检查重复上报、跨设备身份、机器人、客户端丢失、延迟、改名和版本迁移。异常排除必须有预先规则或可复核的数据质量理由，并公布数量及对结果的影响。

随机实验要核对实际分配与预设比例、入组资格和曝光日志。观察到偏差不等于已诊断问题；用适合分配方案的检查判断是否异常，再追踪原因。未解释的样本比例异常可能使结论失真，不能靠删样本“配平”。自然前后批次不具随机分配，不能套用这一检查把它变成随机实验。

数据不可信时可交付测量修复与验证方案；不能在指标定义变化后仍对历史两率做显著性检验来证明产品改善。

## 根据可取得的证据选择设计

| 设计 | 适用条件 | 解释边界 |
| --- | --- | --- |
| 现有使用/工单/订单分析 | 已有数据，先寻找价值与失败模式 | 可能存在人群、渠道、时间及自选偏差 |
| 限量试用与真实任务跟踪 | 用户少，需确认独立价值、支持成本和复用机会 | 记录受助、招募与观察效应；不能外推总体转化 |
| 随机对照 | 可稳定分配、流量与时间足够，干预相互影响可控制 | 先验证分配、数据、样本量与分析方案，再判断效应 |

同一人的前后任务可能受学习与顺序影响；对照任务和顺序需要设计。不同批用户的前后增长可能由招募改变造成。方法不具备识别条件时直接说明因果未知，不强行输出提升结论。

## 实验简报中的关键取舍

- **假设与反例：**目标人群、改变的唯一主要因素、预期价值及会否定它的观察。多因素同时改变时，结论限于整个组合。
- **主指标与护栏：**主指标对应用户结果；护栏记录质量、损失、支持成本或服务负担。数据质量指标用于判断实验能否解释，不能用业务改善抵消记录失真。
- **阈值：**最小值得投入的改善、可承受损失和成本上限来自既有验收、单位经济性或明确业务取舍。尚无基线时先测基线，不引用行业百分比冒充通过线。
- **样本与窗口：**依据可信基线、希望识别的效应、不确定性、分配单位、关联结构和可用流量制定。没有这些输入不虚构“每组多少人必够”；统计差异与超过商业最小收益是不同问题。
- **停止与分析：**预定观察成熟条件、分析时点、预算和紧急停止条件。固定样本方案不能反复查看直到显著再停；若采用连续监测，事前选择适用方法并保留规则。安全/损失停止可优先执行，但仍如实报告不完整效果证据。
- **对比：**报告绝对变化（比例用百分点）、相对变化、计数及不确定性。基线为零时相对增长不可定义；小样本不要输出精确尾部或细分结论。多个指标/分组探索与预定主要判断分开，避免挑选胜利结果。

最终判定可为继续、调整、停止或证据不足。区间跨越业务门槛不代表达标；无显著差异不等于两版等效。护栏或数据质量不满足时，不用漂亮主指标抵消。下一步写明负责人/入口、需要的证据和何时复核；未获联系、收费或发布授权时只准备具体材料。

## 方法来源与范围

以下为本项目原创操作说明，2026-10-26 核对来源；未引入这些机构的通用成功阈值。

- [Google HEART 论文简介](https://research.google/pubs/measuring-the-user-experience-on-a-large-scale-user-centered-metrics-for-web-applications/)：用户目标与用户中心指标之间的映射，适用于选择指标；这里不要求每个项目填满 HEART 各类。
- [Microsoft 样本比例异常研究](https://www.microsoft.com/en-us/research/publication/diagnosing-sample-ratio-mismatch-in-online-controlled-experiments-a-taxonomy-and-rules-of-thumb-for-practitioners/)：随机实验中的分配异常可能反映数据质量问题，需调查再解释效果。

具体统计模型、价格与平台埋点能力需要时再查对应官方资料和项目实现。本文件不提供一套自动替业务作决定的统计工具。
