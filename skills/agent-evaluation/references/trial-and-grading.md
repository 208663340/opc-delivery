# 运行与判分方法

## 任务、oracle、trial 分离

任务是输入与可用环境；oracle 是评估者持有的允许结果、约束及判据；trial 是某一冻结版本的一次真实尝试。不要把 oracle、隐藏故障脚本或其他模型输出交给被测 Agent。文件路径分开还不够：检查上下文拼装、检索和工具可读范围。

先验证任务可解且约束不矛盾。准备参考结果或由独立检查确认可完成；参考路径只证明有解，不强迫 Agent 走同样步骤。版本修改要保留旧任务标识或修订号，不能用改答案来掩盖版本回归。

数据源标明合成/真实、使用范围和脱敏。划分任务开发集与任务保留集，防止同源近重复跨组；保留集用于独立检验，不能在每次提示修改时反复查看后还称未见。judge 的校准/验证划分单独维护，不代表被测 Agent 未见这些任务。

## 运行前固定什么

| 对象 | 必须能够追溯 |
| --- | --- |
| 任务 | 输入、fixture、oracle 和评分规则版本/哈希、来源与 split |
| Agent | 模型实际标识、提示、代码、采样参数与支持差异 |
| 工具与环境 | schema、权限、替身/真实服务、初态、时间/外部数据、状态 owner |
| 资源 | 总时间、调用/token/重试预算、计费单位与失败计费；恢复不能刷新累计限额 |
| 运行 | case/trial/attempt 标识、重置方式、执行顺序、异常与补跑规则 |

同条件配对比较，每个任务预定重复次数；需要时平衡两版先后顺序以减少环境漂移。只改模型、提示、工具或运行时中的目标因素；多个因素一起改变就只能评价整个版本组合。不同模型不支持同一随机参数时说明，不能只靠相同 seed 宣称复现。

状态隔离包括持久化记录、会话、缓存、文件、时间与预算；恢复测试则重建指定 checkpoint 和已发生的副作用。用稳定业务操作标识查询最终状态，记录真实 commit 次数，不能只数 Tool 调用或相信 canned 成功返回。故障/取消注入未实际发生的 trial 不证明对应能力通过。

## 判分顺序与证据

1. **执行有效性：**是否运行了指定版本，初态与故障是否成立，证据是否完整。基础设施失效、任务无解、缺快照分别记录原因；保留原始运行，不静默删除或用补跑覆盖。
2. **硬约束：**权限、确认、取消生效后行为、业务数据完整性、重复写入及资源上限。使用项目已有契约；必要等待是正确结果，已授权工作无故拒绝则不能靠“零副作用”得到成功。
3. **结果质量：**确定性检查能判的交给代码和状态快照；语义判断用明确、任务相关的锚点，例如事实正确、满足主要目标、限制说明准确。缺证据记未知，不能从自述补成功。
4. **诊断：**关联安全摘要、工具结果和权威状态定位第一处偏离。不同合法调用顺序可得到同样结果；确有授权先后或取消约束时才检查必要的顺序。

字段示例中的 `completed` 是语义标签，映射现有终态即可；不要为模板改生产状态。输出、工具调用、最终状态是不同证据，不能互相替代。只收集必要结构化动作和结果，不要求内部思维链或凭据。

## 语义评分器校准

给每个评分维度定义可观察锚点和典型反例。先验证简单事实检查，再对确需语义判断的部分使用人工或模型判分。校准材料包含正确、部分、失败与具有迷惑性的自述，来源标签及实际复核者明确。

盲化待比较版本身份，必要时平衡成对答案顺序；检查长度偏好、措辞偏好和输入中的指令诱导。Agent 输出是待评材料，不能获得修改评分规则的权限。记录分歧、错误接受/拒绝及人工推翻；总体一致率可能掩盖罕见严重错误，按风险类别检查。

校准后冻结 judge 与规则，再用独立校准验证材料检查。没有专家标签时先交付待校准方案或将自动分作为辅助；不得编造“人工已通过”。评审质量门槛从任务后果和可接受错误决定，不预设通用一致率数字。

## 汇总时保留分母

- 每任务与每风险类别同时报计划运行、实际运行、可判分、确认通过、失败、未知与无效运行。说明主成功率分母；无效环境另列，并展示其对覆盖的影响，不能只选成功的可评分样本。
- 对每任务执行 k 次时，列单次通过情况、“至少一次通过”的任务比例与“k 次全通过”的任务比例。这些是本次样本观察；若使用 pass@k / pass^k 名称，写明计算方法和适用假设，不把相关试验直接代入独立同分布公式。
- 对齐同一任务报告改善、回归、持平、无法判断；不能让大量简单题掩盖确认绕过等关键失败。训练/调参用过的回归集与任务保留集分别报告，别拼成一个泛化分数。
- 费用包括所有尝试、重试、工具与可归属基础设施开销，区分实际账单与估算。缺失不填零；只有计费范围和分母完整时才比较单位成功成本，失败开销也计入总成本。币种、价格日期、缓存和折扣条件说明。
- 延迟定义起止与队列/执行/清理范围，报告全 trial 与成功子集，超时保留实际截止观测并标未完成。附样本量、超时/缺测数；小样本 p95 只是样本统计，不保证线上尾部。

预定的业务验收与风险约束先于优化成本。模型更便宜、judge 分更高、所有任务偶尔成功，都不足以直接替换当前版本。

## 从失败回到最小修复

可按需要标记：任务/数据、检索与上下文、规划/选择、工具参数或执行、权限、状态/恢复、终止/预算、评分器、运行环境。允许未知根因；标签只是索引，需要原始证据支持定位。

为最早可复现偏离建立回归，修已有 owner。明确哪些记录只是工具替身，哪些实际执行了模型、故障与持久化；已通过单元或格式校验不能替实际 Agent 运行背书。修复后回归与未见任务分别验证，再决定是否具备授权范围内的下一步条件。

## 方法来源与范围

本项目原创流程与字段示例，2026-10-26 核对以下一手资料，未引入供应商依赖或预设成功率：

- [Anthropic：Demystifying evals for AI agents](https://www.anthropic.com/research/demystifying-evals-for-ai-agents)：实际环境结果区别于最终回复，评分方法需适配任务，重复尝试中的“至少一次”和“每次”回答不同问题。
- [OpenAI：Evaluation best practices](https://developers.openai.com/api/docs/guides/evaluation-best-practices)：明确目标、使用代表性与边界任务、按特定标准评价并持续比较；数据和评分需要实际校准。

供应商运行参数、计费和工具 API 使用时再核对对应版本官方文档。本 Skill 提供评测方法；真实预算、执行权限与生产验收仍来自当前项目。
