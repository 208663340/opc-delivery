# 新用户首份报告激活

目标：生产新用户在注册后 24 小时内完成并查看首份有效报告。观察 7 个完整自然日，再决定是否扩大覆盖。
约定扩量条件：目标版本生产业务冒烟通过；7 日成熟窗口且至少 30 名真实新用户；激活率不低于 60%；关键任务错误率不高于 1%。条件未满足时维持当前覆盖。
事件口径 v3：registered 为入组；report_viewed 且 valid=true 为激活。排除 internal=true，按 user_id 去重，注册后 24 小时内才计入激活。
现有 owner：发布维护者管版本和冒烟；数据管理员管只读事件访问；产品负责人接回价值判断并决定覆盖。
现有工具：python3 tools/metrics.py。本轮已复核为 3.2.0；旧笔记的 metrics export --prod 已不适用，当前接口为 status --env prod 和 events --env prod。
主记录只用本文件。当前状态：已接回研发与分析材料；本次可做的离线只读检查完成，生产业务验证与激活验证未完成，今天不支持扩全量，按既定约定维持当前 10% 覆盖。

## 2026-10-26 接回结论

原目标、事件口径 v3 和全部扩量门槛不变。研发的“上线成功”只能接收为交接陈述，所附冒烟不能证明目标版本生产业务通过；分析的“4 位都完成”不能作为真实生产新用户激活率。今天的结论是**不扩量，维持当前覆盖**；不是已证实产品无效，也不是已证实生产业务失败。本次未部署、未改变覆盖、未改权限、未发消息。

证据来源为本目录的 `reports.md`、`smoke.json`、`events.csv` 和实际执行的本地工具。`tools/metrics.py` 明示为离线合成只读 CLI；其结果可复核案例内状态，但本次没有连真实生产，不能称为线上实测或新完成的生产冒烟。

## 下一位接手者可执行的步骤

以下是交接说明，尚未向任何人发送或执行外部操作；继续使用本文件作为唯一主记录。当前范围只允许本地读取和更新本文件，后续账号操作、线上冒烟或覆盖变更须由有对应权限的现有 owner 按现有流程执行。

1. **发布维护者补 B/prod 证据**：接收 `smoke.json` 与 status 结果，先核对实际生产仍为 B 和当前部署标识，再提供同版本同环境的业务冒烟记录。记录执行时间、版本/部署标识、测试身份的安全引用、创建首份有效报告并查看的结果及可定位证据。若已有有效记录，优先复用；否则在获准环境和身份下执行。缺证据保持“未验证”；若业务路径失败，退回发布维护者调查，不能进入扩量判断。本轮没有足够证据要求重部署。
2. **数据管理员恢复只读事件取证**：接收退出 3 的 `missing_scope` 及所需 `events:read:prod`，通过现有访问流程核实该账号 scope。不要把 valid 登录当成已获事件权限，也不要提供明文凭据。具备权限的接手者确认前提改变后，在本目录依次执行：

   ```bash
   python3 tools/metrics.py status --env prod
   python3 tools/metrics.py events --env prod
   ```

   先确认 B/prod、覆盖和 schema 仍匹配，再读取事件。若仍缺 scope，保留返回和阻塞，继续独立收集冒烟证据；不要循环重试。本案例脚本是固定模拟返回，真实权限恢复不会自动改变其输出；进入真实环境须由数据管理员提供现有生产只读入口及访问证据，不能修改脚本制造成功。
3. **数据管理员/分析职责准备可复核统计**：按原 v3 提供目标版本生产的注册与有效查看事件、user_id、internal 标记、事件时间戳及其时区，并核对报告有效完成/查看状态、事件重复和采集缺失；另提供同观察口径的关键任务总数与错误数及定义来源。先由产品负责人沿用或明确尚缺的自然日时区、准确起止时间、数据截止时间及关键任务口径，不能自行改验收。保留所有合格注册用户作分母，按 user_id 去重，匹配注册后 24 小时内 `report_viewed && valid=true` 作分子。分别列出合格入组人数、满 24 小时人数、尚未成熟人数和采集缺失人数，未成熟/缺失不能直接记为失败或静默排除。
4. **产品负责人接回决定**：先等待实际满 7 个完整自然日，并让所纳入注册用户的 24 小时结果窗口成熟；仅有“age_days=2”不足以指定精确复核日期，需以运行/观察起始时间和确认的时区计算。交回同版本生产冒烟、窗口起止与截止、真实新用户 n、激活 a/n、关键任务错误 e/t 及原始证据引用，在本文件逐项核对全部原门槛。窗口不足、人数不足、采集缺失或任一条件不满足时继续维持覆盖；所有条件均有证据满足后，才交产品负责人决定覆盖，门槛满足本身不授权本轮自动扩量。若版本/事件口径变化，只重验受影响项，不沿用失效的 A/staging 或旧窗口结论。

**恢复入口**：发布证据缺口和数据 scope 缺口可独立推进；缺口补齐后从上面第 2 步重新核对状态，再完成成熟窗口统计。等待时间不会自动补齐权限或证明业务通过。本次方法来自指定技能快照 `../../skill/SKILL.md`（opc-delivery 0.6.0）、其发布/交接参考及包内 `product-value-validation`，未引入另一套主记录或安装分析工具。
