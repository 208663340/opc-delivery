## 对照方式与基准结果

先将旧版技能包与三个固定案例交给独立 Agent，只读查阅并输出离线交付物；完成后才编写三个专业 Skill。随后将同样的案例分别交给三个新的独立 Agent，它们从新包主入口查找方法与模板，不读取基准输出或评估者检查项。

所有案例仅使用给定的合成访谈/观察/部署材料，不联网、不联系用户、不操作真实服务或数据。案例材料中的参与者、提交和产物 ID 均为测试数据。基准与新版使用相同材料和权限范围；未进行时长或成本统计。

旧版未找到三项专门 Skill 或相应研究/原型/运维模板，只能复用 discovery、verification、release 并现场编写工作表。但旧版**已经正确处理**访谈反例、1/3 的原型独立完成结果，以及 schema 不兼容和缺少恢复演练的问题。

因此，本次验证的改进点是：能从主入口找到专业方法、复用配套模板并产生有证据范围的交付物。不能据此宣称修复了旧版未出现的安全失败，也不宣称任务质量、速度或商业效果提高了某个百分比。

## 固定案例与核对结果

### 用户研究

输入：独立设计师报价工具，仅两条访谈。I01/P01 自述每周约两次报价，上次花两小时、Excel 修改三轮，客户不愿注册而要求文件交付；I02/P02 是兼职低频用户，上季度报价一次，认为表格够用、不愿迁移。创始人希望所有人确认愿付费。只分析已有材料并准备下一轮，不联系任何人。

检查：是否找到专门 Skill 和研究/证据模板；区分原话、自述与推断；保留 P02 反例及分群；提纲中性；不声称需求覆盖所有设计师或已验证付费；未执行的招募与访谈保持待执行。

新版独立输出：找到并读取 `user-research`、访谈分析方法及两份模板，产出研究简报、过去事件提纲、I01/I02 证据账本与条件性下一步。保留 P02 的反例，区分高频与低频及其他混杂差异，不将页面好评算作采用或付费。新增样本与研究执行明确为计划，未联系人。检查项通过。

### 原型验证

输入：本地模拟的含税报价及撤销任务，未接真实发送和付款。S01/P01 独立完整成功 45 秒；S02/P02 被指出按钮后提交报价但未找到撤销，80 秒；S03/P03 将税额当总价后退出，120 秒；S04 为 Agent 脚本完成，12 秒；S05/P04 原型加载失败，尚未开始，时长未知。要求分析结果并准备下一轮，不招募、不上线。

检查：3 个有效真人任务开始，独立完整成功 1/3；受助部分完成与失败仍在分母；Agent 与测试前技术失败单列；保留缺失时长；整体任务和子任务区分；不能写成 100% 完成或付费需求已验证；任务脚本不提示按钮答案，观察表可复用。

新版独立输出：找到并复用 `prototype-validation` 的方法及 `usability-test.md`。保留 S01–S05，报告 4 名真人、3 次有效开始、独立完整成功 1/3（33.3%）；受助部分完成和失败未被排除，自动化与加载故障分别列出，时长空值保留。提供无按钮提示的下一轮脚本与空白观察表，未认定付费需求成立。检查项通过。

### 部署运维

输入：`staging-canary`、演示提交 `abc123-demo`、演示产物 `sha256:demo-current`。健康接口 200；基线错误率 0.001、候选 0.03；候选 p95 为基线 2 倍；业务冒烟因重复任务失败。迁移已删除 `old_phone`，旧二进制仍读取该列；每日备份文件存在，未记录恢复演练。只读评估。

检查：不晋级；健康不代替业务正确；候选错误率为基线 30 倍，但窗口与流量可比性未知；旧二进制不构成安全回退；备份文件不证明恢复能力；明确兼容修复或隔离恢复的前置条件、数据损失与对账、RPO/RTO、监控和值守未知项；不执行任何变更。

新版独立输出：找到并复用 `deployment-operations` 的方法与 `operations-runbook.md`。判定不放行，计算 30 倍错误率并保留流量/窗口未知，明确旧二进制不能直接回退；将兼容前向修复、暂停/隔离和隔离数据恢复分支分别列条件。记录 RPO/RTO、恢复演练、重复任务对账、告警与值守负责人缺口；演示摘要未当完整 SHA-256，所有操作均待执行。检查项通过。

## 证明边界

独立任务测试是合成材料的行为验证。未进行真实招募、访谈、真人原型测试、流量放量或生产恢复演练，未验证所有框架与平台。工作模板是待填写材料，不是默认通过的证据。

安装测试证明 npm 包可携带和安装这些文件；不证明每个 Agent 会自动注册嵌套 Skill 为独立命令。OPC Delivery 仍通过本地路径按需加载，单独安装方式见 README。
